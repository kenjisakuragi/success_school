# 🎯 設計原則(これだけは死守)

## ルール1: 「考えない」設計

❌ 毎回「今日何しよう?」と考える
✅ **曜日と時間で、やること・使うプロンプトが固定されている**

## ルール2: Yes/No判定だけで進める

❌ AIの出力を細かく修正する
✅ **「OK / もう1回 / 没」の3択だけ**

## ルール3: AIに次の行動も決めさせる

❌ Kenjiが「次は何をする?」と考える
✅ **AIの出力の最後に必ず「次のアクション」を出力させる**

## 結果:Kenjiの1日の意思決定回数を10回以内に抑える

(意思決定疲れの研究: 1日3500回の判断で消耗。経営者は重要判断だけ残す)

# 🔁 §8 Make.comで自動化する10の連携(これが本体)

これがKenjiの「脳を疲れさせない」核心:

1. **Claude出力 → Notion保存** (生成稿が全てログ化される)
2. **Notion「公開OK」マーク → Buffer予約投稿** (Xに自動配信)
3. **noteのRSS → LINE一斉配信** (新記事更新時に登録者に通知)
4. **YouTube公開 → Brevoメルマガ通知** (新動画通知)
5. **Brevo登録 → Notion CRMに自動追加** (顧客DB自動更新)
6. **Stripe決済 → Notion売上ログ + LINE通知** (売上発生をKenjiにプッシュ)
7. **本科申込 → LINE伴走Botにユーザー追加 + Brevoシーケンス起動** (オンボ自動)
8. **NPSスコア低下 → Slackに警告通知** (解約予兆検知)
9. **VIP申込 → カレンダーに自動Zoom予定追加 + Kenjiにメール** (1on1の準備自動)
10. **週末22時 → AIに「今週のKPI分析依頼」→ Slackに結果通知** (月曜朝に答えが届く)

**設定工数: 各30分 × 10連携 = 5h(M1で完了)**
**以後の保守: 月1h以下**

# 💡 §12 Kenjiが「やりがちな罠」とその回避

| 罠 | 兆候 | 回避法 |
|---|---|---|
| **修正魔になる** | AI出力を「ここをもう少し…」と何度も修正 | **3回まで再生成。3回でNGなら別プロンプトに切替** |
| **完璧主義** | LP・PDFが永遠に公開できない | **80点で必ず公開。改善は公開後** |
| **コンテンツ自分書き** | 「AIより自分の方が上手い」気がする | **Kenjiが書くと週稼働40hに戻る。AI80点+量で勝つ** |
| **VAに頼りたくなる** | 単純作業に時間取られる | **§10の判断基準に従う。感情で決めない** |
| **本業を理由に止める** | 「TBSが忙しくて…」 | **週6h(土+毎晩30分)は確保。これ以下なら計画失敗** |
