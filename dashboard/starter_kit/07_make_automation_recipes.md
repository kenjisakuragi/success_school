# 🔗 Make.com連携10本の具体レシピ

> **使い方:** Make.comに登録後、下記10シナリオを順番に構築 → これでKenjiの手作業が消える
> **所要:** 各30分 × 10 = 5時間(M1 Week 1-2で完了推奨)
> **目的:** 「考えずに事業が回る」自動化の核

---

```
[コンテンツ生成]

       ↘ Drive → 共有

[集客]

   → 7日後セミナー誘導 → Stripe → 売上記録

[運用]

NPS低下 → Slack警告 → Kenji対応キュー

[Kenjiは「OKボタン」を押すだけ]
```

# 🔧 各シナリオの構築手順

## 🟢 シナリオ1: Claude出力 → Notion自動保存

**目的:** AI生成稿が散逸しない。Notionに「未承認コンテンツDB」として蓄積

### モジュール構成
```
[Trigger] Webhook (Claude APIから受信)
   ↓
[Action] Notion - データベースに新規レコード作成
   - タイトル: Claude出力のタイトル部分
   - コンテンツ: 本文
   - ステータス: 未承認
   - 作成日時: 自動
```

### 設定値
- Notion DB: 「コンテンツプール」
- ステータス選択肢: 未承認 / 承認済 / 公開済 / 没

### Kenji手作業: なし
### 月次稼働: 自動・無限

---

## 🟢 シナリオ2: Notion「公開OK」マーク → Buffer予約投稿

**目的:** Kenjiが Notion で「公開OK」にしたら、自動でXに投稿予約

### モジュール構成
```
[Trigger] Notion - レコード更新(ステータスが「承認済」になったら)
   ↓
[Filter] コンテンツ種別 == "X投稿"
   ↓
[Action] Buffer - 新規投稿を作成
   - 投稿時刻: 当日 19:30(夜の最強タイム)
   - チャンネル: X
```

### Kenji手作業: Notionで「承認済」ボタンクリックのみ
### 効果: 投稿スケジューリング完全自動化

---

## 🟢 シナリオ3: noteのRSS → LINE一斉配信

**目的:** noteに新記事公開時、LINE登録者に自動通知

### モジュール構成
```
[Trigger] RSS - note.com/sakuragi_kenji の新着監視
   ↓
[Action] LINE Official Account - 一斉メッセージ送信
   - 件名: 「新作noteを公開しました🌹」
   - 本文: 記事タイトル + リンク + 短い案内
```

### 注意
- 一斉配信は週1回までに制限(ブロック率対策)
- 配信時刻: 火曜 or 金曜の19時推奨

### Kenji手作業: noteの「公開」ボタンを押すだけ

---

## 🟢 シナリオ4: YouTube公開 → Brevoメルマガ通知

**目的:** YouTube新動画公開時、メルマガ登録者に通知

### モジュール構成
```
[Trigger] YouTube - 新規動画公開を検知
   ↓
[Action] Brevo - キャンペーン送信
   - リスト: 全LINE登録者
   - 件名: 「【新作】YouTube動画を公開しました」
   - 本文: 動画タイトル+サムネ+CTAボタン
```

### Kenji手作業: YouTubeの「公開」ボタンのみ

---

## 🟢 シナリオ5: Brevo登録 → Notion CRM自動追加

**目的:** 新規LINE登録者を、Notion顧客DBに自動追加

### モジュール構成
```
[Trigger] Brevo - 新規コンタクト追加
   ↓
[Action] Notion - 顧客CRM DBにレコード作成
   - 名前: コンタクトの名前
   - メアド: 同上
   - LINE ID: ある場合
   - ステータス: 新規LINE登録
   - 登録日: 今日
   - LTV予測: ¥0(後で更新)
```

### Notion CRM DB構造
```
顧客CRM
├ 名前 (テキスト)
├ メアド (メール)
├ LINE ID (テキスト)
├ ステータス (Select: 新規/PDFDL/セミナー参加/本科生/サブスク/解約)
├ 登録日 (日付)
├ LTV (数値)
├ 最終接触日 (日付)
└ メモ (テキスト・長文可)
```

### Kenji手作業: なし

---

## 🟢 シナリオ6: Stripe決済 → Notion売上ログ + LINE通知

**目的:** 売上発生時、即座にKenjiに通知 + DB更新

### モジュール構成
```
[Trigger] Stripe - 新規決済成功
   ↓
[Action 1] Notion - 売上DB レコード追加
   - 商品名: 桜木賢治本科 / セミナー / VIP 等
   - 金額: 決済額
   - 顧客メアド: 自動取得
   - 決済日時: 自動
   ↓
[Action 2] LINE(Kenji個人) - プッシュ通知
   - 「🎉 売上発生: ¥XX,XXX / 商品: XXX」
   ↓
[Action 3] Notion CRM - 該当顧客のステータス更新
   - 「セミナー参加」「本科生」等に変更
```

### Kenji手作業: 通知見て「やった」と喜ぶだけ
### 効果: 売上が逃げない・追跡もれゼロ

---

## 🟢 シナリオ7: 本科申込 → LINE Botオンボ + Brevoシーケンス起動

**目的:** 本科申込者に即座にオンボーディング開始

### モジュール構成
```
[Trigger] Stripe - 「本科Standard」or「本科VIP」決済成功
   ↓
[Action 1] LINE - 該当ユーザーを「本科生」グループに追加
   ↓
[Action 2] Brevo - 「本科生21日シーケンス」を起動
   ↓
[Action 3] Google Calendar - Kenji個別Zoom(VIPのみ)の枠を自動予約
   - 申込から3日以内の空き時間
   ↓
[Action 4] Slack #売上 - 「🎉 新規本科生: [名前]」通知
```

### Kenji手作業: VIP個別Zoomに登壇するだけ

---

## 🟢 シナリオ8: NPSスコア低下 → Slack警告

**目的:** サブスク解約予兆を検知して、事前にケア

### モジュール構成
```
[Trigger] Google Forms - 月次NPSアンケート回答
   ↓
[Filter] スコア <= 6(検出基準)
   ↓
[Action 1] Slack #alerts - 「⚠️ NPS低下: [顧客名] スコア[X]」
   ↓
[Action 2] Notion CRM - 該当顧客に「要フォロー」フラグ
   ↓
[Action 3] Brevo - 個別フォローメール自動下書き作成(Kenji推敲用)
```

### Kenji手作業: 月1で要フォローリストを見て、必要なら個別連絡

---

## 🟢 シナリオ9: VIP申込 → Zoom自動予定 + Kenji通知

**目的:** VIP契約者の1on1を確実に組む

### モジュール構成
```
[Trigger] Stripe - 「本科VIP」決済成功
   ↓
[Action 1] Calendly - 自動でユーザーに予約リンク送付
   - 利用可能枠: 土曜午前(Kenji稼働可能日)
   ↓
[Action 2] 予約確定後 → Zoom - 自動でミーティング作成
   ↓
[Action 3] Google Calendar - Kenji+顧客のカレンダーに追加
   ↓
[Action 4] LINE(Kenji) - 「🎯 VIP個別Zoom予定: [日時] [顧客名]」
```

### Kenji手作業: 予定通りZoomに登壇

---

## 🟢 シナリオ10: 週末22時 → AI週次分析 → 月曜朝Slack通知

**目的:** 月曜朝、Kenjiが「今週何をすべきか」を即座に把握

### モジュール構成
```
[Trigger] Schedule - 毎週土曜22:00
   ↓
[Action 1] Notion - 今週の数値を集計
   - LINE登録純増 / 売上 / コンテンツ公開数 / Kenji稼働
   ↓
[Action 2] Claude API - 集計値を渡して週次レポート生成
   - プロンプト: 「これらの数値から、来週やるべきことを3つ提案」
   ↓
[Action 3] Slack #ai-output - 月曜朝7時に予約投稿
   - レポート全文
   - 3つの提案
   - 「☐ OK / ☐ 修正」ボタン
```

### Kenji手作業: 月曜朝にSlackを見るだけ
### 効果: 戦略的判断の自動化

# 🛠️ Make.com の構築テクニック

## エラーハンドリング(必須)

各シナリオに「Error Handler」を追加:
```
[Module失敗時]
   ↓
[Action] Slack #alerts に通知
   - 「⚠️ Make.com Error: [シナリオ名] / [モジュール名] / [エラー内容]」
```

これがあれば、自動化が壊れた瞬間にKenjiが気づける。

# 🚨 トラブル時のフォールバック

各シナリオが壊れたら、Slack #alertsに通知が来る。
そこから対話Claude(私)に「シナリオXが壊れた、エラー[内容]」と相談すれば、即座にデバッグ手順を提示します。

3つのシナリオが同時に壊れた場合:
1. Make.comの稼働状況を確認(https://status.make.com)
2. それでも復旧しなければ、対話Claudeに連絡
