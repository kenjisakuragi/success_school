## 4. Stripe決済連携設定

### 4-1. APIキー登録

1. 左サイドバー **「設定」** → **「決済連携」** → **「Stripe」** タブ。
2. Stripeダッシュボード(`dashboard.stripe.com`)で:
   - **開発者** → **APIキー** → **公開可能キー**(`pk_live_...`)と **シークレットキー**(`sk_live_...`)を取得。
   - ※テスト中は `pk_test_` / `sk_test_` を使用。
3. UTAGE側に2つのキーを貼付 → **「接続テスト」** → 「成功」表示を確認。
4. **Webhookエンドポイント** をStripe側に登録:
   - UTAGE管理画面に表示される `https://utage.jp/webhook/stripe/xxxx` をコピー。
   - Stripeダッシュボード → **開発者** → **Webhook** → **エンドポイント追加** → 貼付。
   - イベント:`checkout.session.completed` / `invoice.payment_succeeded` / `invoice.payment_failed` を選択。

### 4-2. 商品登録

UTAGE側ではなくStripe側で先に「商品(Product)」を作っておくと管理が楽:

| 商品名 | 価格 | 支払形態 |
|---|---|---|
| マスター講座 | ¥19,800 | 一括 |
| Manifest AI™ | ¥88,000 | 一括 / 3回 / 6回 |

各商品の `price_id`(`price_xxxx`)をメモ → UTAGEの商品設定欄に貼付。

### 4-3. 分割払い設定(Manifest AI™ のみ)

1. Stripe側で **「定期支払い」** ではなく **「分割払い(Installments)」** を有効化。
   - ※Stripe Installments は日本では限定的なので、実務上は **「3回分割 = ¥29,400 × 3」** のサブスクリプション商品を別途作成する方式が確実。
2. UTAGE側 → 商品設定 → **「支払い方法」** で「一括」「3回」「6回」を選択肢として並べる。
3. 銀行振込:UTAGE標準機能の **「銀行振込」** をON → 入金確認は管理画面 **「注文管理」** タブから手動承認。

**所要時間目安: 45分**

## 5. Evergreen Timer の設定(30分・本当に閉じる)

### 5-1. タイマー追加

1. 対象ページ(OTO / Upsell)のエディタで **「+ ブロック追加」** → **「カウントダウンタイマー」** → **「Evergreen(訪問者ごとに開始)」** を選択。
2. 設定パネル:
   - **カウント時間**: `30分`
   - **開始トリガー**: 「ページ初回訪問時に開始」
   - **訪問者識別**: 「Cookie + メールアドレス(ハイブリッド)」を選択 ★重要
   - **タイマー切れ後の挙動**: **「指定URLへリダイレクト」** → `⑥Expired` のURLを指定
   - **再訪問時の挙動**: **「リダイレクト(タイマーは復活させない)」** ★重要

### 5-2. 「本当に閉じる」設定

ここを誤ると不正な再アクセスで割引が無限に使われる:

1. タイマー設定パネル下部の **「セキュリティ」** タブを開く。
2. 以下を全てONに:
   - ☑ **Cookie削除でもタイマーをリセットしない**(サーバー側でメールアドレス紐付け保存)
   - ☑ **シークレットウィンドウからのアクセスでも同一ユーザー扱い**(メールアドレス必須化)
   - ☑ **タイマー切れ後の決済ページアクセスを禁止**(直URL叩いてもExpiredに飛ばす)
3. **「保存」**。

### 5-3. テスト

1. シークレットウィンドウで該当ページにアクセス → タイマーが30分から始まることを確認。
2. 一旦閉じて、5分後に再度アクセス → タイマーが約25分から再開されることを確認(リセットされない)。
3. タイマー切れ後にアクセス → Expiredへリダイレクトされることを確認。

**所要時間目安: 30分**

## 6. メールシーケンス3ルート×10通の登録手順

参照: `email_sequence_v1.md`

### 6-1. 3ルートの定義

| ルート | 対象タグ |
|---|---|
| A: 購入者(両方) | `buyer_manifest_ai` |
| B: 購入者(マスターのみ) | `buyer_master_course` AND NOT `buyer_manifest_ai` |
| C: 非購入者 | `lead_optin_vsl` AND NOT `buyer_master_course` |

### 6-2. シナリオ作成

1. 左サイドバー **「メール」** → **「シナリオ」** → **「+ 新規シナリオ」**。
2. シナリオ名: `Route_A_FullBuyer` 等、3つ作成。
3. 各シナリオの **「対象セグメント」** タブで上記タグ条件を設定。

### 6-3. メール10通の登録(各ルート)

1. シナリオエディタで **「+ メール追加」** を10回。
2. 各メールに以下を入力:
   - **配信タイミング**: 「シナリオ開始から X時間後」 or 「前のメール送信から X時間後」(`email_sequence_v1.md` のスケジュール表に従う)
   - **件名 / 本文**: `email_sequence_v1.md` の該当メールをコピペ
   - **差し込み変数**: `{name}` `{first_name}` 等は UTAGE 標準変数に置換
3. **「除外条件」** 設定:
   - ルートCの途中で購入が発生した場合は **「`buyer_master_course` 取得時にシナリオ停止」** を設定。
   - ルートBの途中でUpsell購入した場合も同様に **「`buyer_manifest_ai` 取得時にルートAへ自動移行」**。

### 6-4. トリガー設定

| ルート | 開始トリガー |
|---|---|
| A | タグ `buyer_manifest_ai` 付与時 |
| B | タグ `buyer_master_course` 付与かつ 24時間以内に `buyer_manifest_ai` なし |
| C | タグ `lead_optin_vsl` 付与かつ 24時間以内に `buyer_master_course` なし |

各シナリオの **「トリガー」** タブで上記を設定 → **「有効化」** ON。

**所要時間目安: 90分(コピペ含む)**

## 7. タグ自動付与の設定

### 7-1. タグ一覧(まず先に作成しておく)

1. **「設定」** → **「タグ管理」** → **「+ 新規タグ」**。
2. 以下を全て作成:

| タグ名 | 用途 |
|---|---|
| `lead_optin_vsl` | VSL LP オプトイン完了 |
| `viewed_oto` | OTOページ閲覧 |
| `viewed_upsell` | Upsellページ閲覧 |
| `buyer_master_course` | ¥19,800 購入 |
| `buyer_manifest_ai` | ¥88,000 購入 |
| `passed_oto` | OTO離脱 |
| `passed_upsell` | Upsell離脱 |
| `expired_oto` | OTOタイマー切れ |
| `expired_upsell` | Upsellタイマー切れ |
| `churn_risk` | 離脱兆候(メール未開封3通連続) |

### 7-2. 付与ルール

1. **フォーム送信時**: 各ページのフォーム設定 → 「送信時タグ付与」欄に該当タグを指定。
2. **ページ閲覧時**: ページ設定 → 「閲覧時タグ付与」欄。10秒以上滞在で発火するよう **「滞在時間条件」** を10秒に。
3. **決済完了時**: 商品設定 → 「決済成功時タグ付与」欄。
4. **タイマー切れ時**: タイマー設定 → 「切れ時タグ付与」欄。
5. **離脱兆候**:メールシナリオ側で「3通連続未開封」条件を作り、`churn_risk` を付与するアクションを設定。

**所要時間目安: 30分**

## 付録A: トラブルシューティング早見表

| 症状 | 原因の可能性 | 対処 |
|---|---|---|
| タイマーがリセットされる | Cookie識別のみON | §5-2の「メールアドレス紐付け」をON |
| 決済後タグが付かない | Stripe Webhook未登録 | §4-1のWebhook設定を再確認 |
| メールが届かない | ドメイン認証(SPF/DKIM)未設定 | UTAGE「設定→ドメイン認証」を完了 |
| Make.com に届かない | Webhook URLミス | URLを再コピーしてUTAGE側を更新 |
| Upsellがワンクリックで決済されない | Stripe Customer ID未連携 | OTO側の「顧客情報保存」をONに |
