# 💬 ② 対話の5つの主要モード

## モードA:WOOP実行(ソクラテス対話)

ユーザーが新しい目標を持ったとき、または週次・月次の見直し時に発動。

### トリガー例

- 「3年後の目標、決まらない」
- 「最近、何のために頑張ってるかわからなくなった」
- 「WOOPを書きたい」
- 「もっと深く考えたい」

### Manifest AI™ の対応フロー

```
Step 1. Wish(願望)を引き出す
  AI: 「3年後、あなたがいちばん変わっていたい領域は、なんでしょうか?」

Step 2. Outcome(成果)を五感で立体化
  AI: 「それが叶ったとき、朝起きてどんな景色が見えますか?」
  AI: 「隣には誰がいますか?」
  AI: 「心は、どんな状態になっていますか?」

Step 3. Obstacle(内側の障害)を引き出す
  AI: 「過去、その目標に向かおうとして、止まってしまった経験はありますか?」
  AI: 「そのとき、あなたの "内側" にあった本当の壁は、なんでしたか?」

Step 4. Plan(実装意図)を作る
  AI: 「もし、その壁がまた出てきたら、どんな行動で乗り越えますか?」
  AI: 「『もし___が起きたら、私は___をする』の形で書いてみましょう」

Step 5. WOOPを記録・確認
  AI: 「素晴らしいWOOPができました。Supabaseに保存しました。
       明日の朝7時に、わたしから "実行できたか" 確認しますね」
```

## モードB:未来からの手紙ドラフト生成

ユーザーが手紙を書きたいときに、AIがドラフトを生成 → ユーザーが加筆修正。

### 対話例

```
ユーザー: 「3年後の朝の手紙、書いてみたい」

AI: 「ありがとうございます、{name}さん。
    あなたのWOOPに基づいて、ドラフトを作ります。
    
    ─────────────────────
    2029年5月23日
    
    {name}へ
    
    私は今、{vision}に到達していました。
    
    朝起きると、{visual_morning}が見えています。
    {sound_morning}が聞こえてきます。
    心は{emotion_morning}で満たされています。
    
    3年前のあなたは、{obstacle}を抱えていましたね。
    でも、それを乗り越えたきっかけは、
    {plan_action} を、毎日続けたことでした。
    
    私から、今のあなたへ、ひと言。
    「あの夜、続けてくれて、ありがとう」
    
    2029年5月23日 3年後のあなたより
    ─────────────────────
    
    このドラフトを、あなたの言葉に書き換えてみてください。
    完璧でなくていいです。1段落でいいです」
```

## モードC:毎朝7時の問いかけ(プッシュ)

Make.com Scenario 2 で自動配信。

### Day 1-7(序盤・基本確立)

### Day 8-30(中盤・深化)

ランダムに5パターンから1つを送る:

```
Pattern 1: WOOPチェック
「今朝、あなたのObstacle({obstacle})は、
 今日どこで出てきそうですか?」

Pattern 2: 五感の再活性化
「3年後の朝、あなたは何の匂いに包まれていますか?
 今朝、その匂いを部屋に再現できる方法は、ありますか?」

Pattern 3: セルフイメージ強化
「今日、あなたが『3年後のわたし』だとしたら、
 何時に何をして、誰と話していますか?」

Pattern 4: マネク(招く)宣言
「今日、声に出してください ―
 『わたしは、{vision}を招き入れる人間です』」

Pattern 5: カサネル(重ねる)
「昨日、何か1つでも、3年後への積み重ねがありましたか?
 たとえ5分でも、書いた、呼吸した、話した、なんでも」
```

## テーブル設計

| `outcome_feeling` | text | 五感のうち触覚・感情 |
| `obstacle` | text | 内側の障害 |
| `woop_plan` | text | 「もしXならY」のPlan |
| `last_letter` | text | 最新の「未来からの手紙」(全文) |
| `last_letter_summary` | text | 上記の100字要約 |
| `created_at` | timestamp | レコード作成日 |
| `updated_at` | timestamp | 最終更新 |

| カラム | 型 | 内容 |
|---|---|---|

| `user_id` | uuid | users.id への外部キー |
| `role` | text | "user" or "assistant" |
| `content` | text | メッセージ本文 |
| `created_at` | timestamp | 送受信日時 |
| `tokens_used` | int | Claude APIトークン消費 |

### `weekly_summaries` テーブル

| カラム | 型 | 内容 |
|---|---|---|
| `id` | uuid | プライマリキー |
| `user_id` | uuid | users.id への外部キー |
| `week_number` | int | プログラム何週目か |
| `summary` | text | 1週間の対話要約(Claude生成) |

| `key_topics` | text[] | キートピックの配列 |
| `created_at` | timestamp | 作成日 |

### メモリー戦略(コスト最適化)

```
- 直近5メッセージ → 全文を System Prompt に注入
- 6メッセージ以前 → 週次要約に圧縮 → System Prompt に注入
- 12週間以前(卒業後)→ 月次要約に再圧縮 → 必要時のみ呼出
```

**コスト試算:**
- 1対話あたり ~2K tokens 入力 + 500 tokens 出力
- 1ユーザー月100対話 = 月250K tokens
- Claude Sonnet 4.5: $3/M入力, $15/M出力
- 1ユーザー月コスト = $0.75 + $0.75 = **$1.50(¥225)**
- 100ユーザーで月¥22,500 ← 売上の3%以下に収まる

```

   ↓ (通常)

   ↓
9. conversations に user + assistant のメッセージを保存
   ↓
10. users.last_active_at を更新
```

# 🛠️ ⑧ プロンプトエンジニアリング詳細

## System Prompt 構造(動的部分)

```python
def build_system_prompt(user, conversation_history):
    base = MANIFEST_AI_BASE_PROMPT  # 上述の固定部分
    
    # ユーザー情報を注入
    user_context = f"""
    【ユーザー情報】
    名前: {user['name']}
    プログラム開始日: {user['enrolled_at']}
    今日でプログラム{calc_day_count(user['enrolled_at'])}日目
    3年後のビジョン: {user['vision']}
    五感の詳細(視覚): {user['outcome_visual']}
    五感の詳細(聴覚): {user['outcome_sound']}
    五感の詳細(感情): {user['outcome_feeling']}
    内側の障害: {user['obstacle']}
    WOOP-Plan: {user['woop_plan']}
    最後の手紙(要約): {user['last_letter_summary']}
    """
    
    # 直近の対話履歴を注入(最大5件)
    recent = format_recent_dialogue(conversation_history[:5])
    
    # 今日のタスク(時間帯・状況に応じて)
    daily_task = determine_daily_task(user, conversation_history)
    
    return base + user_context + recent + daily_task
```
